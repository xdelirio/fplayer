fplayer · integration guide

Adding the player to your apps

From zero to a video playing, and what the manifest needs depending on which features you turn on. Everything in the manifest is optional: the plugin declares nothing on its own, so an app that only plays video never has to justify permissions it doesn't use.

What you install

Three packages, deliberately separate. The first one is the only one you almost always want.

PackageWhat forWhen
fplayer The player: Media3/ExoPlayer, UI, tracks, subtitles, TV, PiP, downloads. always
fplayer_telemetry Persistent on-disk queue and batched delivery of metrics to your API. if you report to a backend
fplayer_fvp libmdk/FFmpeg fallback engine for codecs Android doesn't cover. only if you need it
careful

fplayer_fvp weighs 11.5 MB per ABI — over 30 MB with three — against 1–2 MB for all of Media3, and the APK pays for it even if it never kicks in. That is exactly why it sits outside the base package. Add it only if you have content that won't play: in practice, software AV1 on Android below 12.

Installation

It isn't published on pub.dev yet, so you reference it by path or by Git.

# your app's pubspec.yaml
dependencies:
  fplayer:
    git:
      url: https://github.com/chikenare/fplayer.git
      ref: main

  # Or during development, with the repo cloned alongside:
  # fplayer:
  #   path: ../fplayer

The sibling packages live inside the same repository:

  fplayer_telemetry:
    git:
      url: https://github.com/chikenare/fplayer.git
      path: fplayer_telemetry

Android setup

Module requirements: minSdk 24 and compileSdk 36. Flutter 3.44 or newer.

The plugin only declares INTERNET. Everything else goes in your app's manifest, and only if you use the matching feature.

If you use…Add to the manifest
Streams over HTTP without TLS android:usesCleartextTraffic="true" on <application>
Picture-in-Picture supportsPictureInPicture and resizeableActivity on the Activity
Media session or background audio The session <service> and three foreground-service permissions
Background downloads The download <service> and its permissions
Android TV Two <uses-feature> entries marked as not required

Picture-in-Picture

<activity
    android:name=".MainActivity"
    android:supportsPictureInPicture="true"
    android:resizeableActivity="true"
    <!-- the rest as you already have it --> />

Media session and background audio

<uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_MEDIA_PLAYBACK" />
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />

<service android:name="dev.chikenare.fplayer.FplayerMediaService"
         android:exported="false"
         android:foregroundServiceType="mediaPlayback">
    <intent-filter>
        <action android:name="androidx.media3.session.MediaSessionService" />
    </intent-filter>
</service>
note

Without that <service> the session is skipped silently and controller.hasMediaSession stays false. It is checked before anything gets built, so nothing blows up: there is simply no notification and no lock-screen controls.

Background downloads

<uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_DATA_SYNC" />
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
<!-- only to resume after a device reboot -->
<uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED" />

<service android:name="dev.chikenare.fplayer.download.FplayerDownloadService"
         android:exported="false"
         android:foregroundServiceType="dataSync">
    <intent-filter>
        <action android:name="androidx.media3.exoplayer.offline.DownloadService" />
    </intent-filter>
</service>

Without the service downloads still work, but only while the app is alive.

Android TV

<uses-feature android:name="android.hardware.touchscreen" android:required="false" />
<uses-feature android:name="android.software.leanback" android:required="false" />

Minimal integration

One controller, one source, one widget. Nothing else is required.

import 'package:fplayer/fplayer.dart';

class _ScreenState extends State<Screen> {
  late final _controller = FPlayerController();

  @override
  void initState() {
    super.initState();
    _controller.open(FPlayerSource.network('https://cdn.yourapp.com/master.m3u8'));
  }

  @override
  void dispose() {
    _controller.dispose();  // releases the native player and the texture
    super.dispose();
  }

  @override
  Widget build(BuildContext context) => FPlayerView(controller: _controller);
}

FPlayerView sizes itself to the video's aspect ratio, so it drops into a Column without wrappers. If you would rather build your own interface, the layers are available on their own: FVideoSurface, FSubtitleView, FProgressBar, FTrackDialog, FErrorView.

Recipes

Authenticated content

Headers are applied to the manifest request, to every segment and to every range request. An external subtitle gets only its own: the CDN token never travels to a third-party subtitle server. 

FPlayerSource.network(
  url,
  headers: {'Authorization': 'Bearer $token'},
  subtitles: [
    FSubtitleSource.network(
      'https://subs.otherdomain.com/es.vtt',
      label: 'Spanish',
      language: 'es',
      headers: {'X-Api-Key': key},
    ),
  ],
)

Resume where they left off

// When opening
FPlayerSource.network(url, startAt: savedPosition)

// When saving: the event stream avoids writing on every frame
_controller.events.listen((event) {
  if (event is FPositionChanged) saveEvery30s(event.position);
  if (event is FCompleted) markAsWatched();
});

A series that plays straight through

await _controller.setPlaylist(episodes, startIndex: 2);

_controller.value.currentIndex;    // position in the queue
_controller.value.nextInPlaylist;  // what comes next

It moves on by itself when an item ends, and the "up next" card appears near the end. Mark the spans that can be skipped and the button shows up on its own: 

chapters: [
  FChapter(start: Duration.zero, end: Duration(seconds: 45),
           title: 'Intro', kind: FChapterKind.intro),
  FChapter(start: Duration(seconds: 45), title: 'Episode'),
]

Android TV build

FPlayerView(
  controller: _controller,
  config: FUiConfig.tv(),  // remote-first from the first frame, larger chrome
)

In an app that ships to phones and TVs at once you need to do nothing: the default is FTvMode.auto, which changes nothing until the first directional key arrives and shows the focus ring from then on.

Picture-in-Picture

FPlayerController(
  config: FPlayerConfig(pip: FPipConfig(autoEnterOnLeave: true)),
)
careful

The PiP window mirrors the whole Flutter tree, not just the video. Use isPipActive to strip the interface down while it lasts, or the viewer will see your episode list shrunk inside the thumbnail. 

if (_controller.value.isPipActive) {
  return FPlayerView(controller: _controller, config: const FUiConfig.bare());
}

Offline downloads

await FDownloadManager.instance.initialize(
  const FDownloadConfig(requirements: FDownloadRequirements.unmeteredOnly()),
);

final options = await FDownloadManager.instance.inspect(source);
await FDownloadManager.instance.enqueue(
  source,
  selection: const FDownloadSelection.standard(),  // up to 720p
);

FDownloadManager is a ChangeNotifier: listen to it and you have the queue with state, progress and bytes. The part that matters: a finished download plays through the same FPlayerSource.network as always — the cache is keyed by URI, so the place where you call open() has no idea the bytes are local.

Playback metrics

final tracker = FPlaybackSessionTracker(
  controller: _controller,
  observers: [MyObserver()],
);
// ...
tracker.dispose();

It attaches from the outside: it listens to the controller, it does not modify it. It derives real watch time — without pauses or stalls, adjusted for playback speed — time to first frame, rebuffers, quality changes and seeks. To ship that to your API with a persistent queue and retries, use fplayer_telemetry.

Customising the UI

FUiConfig decides what is shown; the builders decide how.

FPlayerView(
  controller: _controller,
  config: const FUiConfig(
    localizations: FPlayerLocalizations.spanish(),
    theme: FPlayerTheme(accent: Color(0xFF00A8E1)),
    showLockButton: false,
    controlsTimeout: Duration(seconds: 3),
  ),
  bottomBarBuilder: (context, ui) => MyBottomBar(ui: ui),
)

Inside any builder, FPlayerScope.of(context) gives you the same view state the built-in controls use — visibility, lock, scrub, fit — so your bar can restart the auto-hide or begin a drag without rewiring anything.

Presets: FUiConfig.bare() leaves only the video (the gestures stay live, to feed your own overlay) and FUiConfig.tv() assembles the leanback layout.

The chrome starts away

Nothing covers the picture until someone asks for it: a tap brings the controls up, and meanwhile a hairline of progress along the bottom edge answers the one question worth answering without one. showControlsOnStart: true restores the old behaviour and showIdleProgressBar: false drops the hairline. FUiConfig.tv() shows the controls on start, because a remote needs something focused to start from.

The controls live at the bottom

Four things are configurable — audio, subtitles, quality, speed — which is not enough to earn a menu. Audio and subtitles share one dialog, side by side, because the decision is one decision; quality and speed each get a control that already reads as its value. 

// Every one of these is a bool on FUiConfig.
showAudioSubtitlesButton   // both track lists at once; hidden when there is nothing to pick
showQualityButton          // reads `Auto · 1080p`; only on adaptive media with more than one rung
showSpeedButton            // reads `1x`
showMuteButton
showFitButton
showFullscreenButton
showSettingsButton         // the catch-all panel: off on touch, on for FUiConfig.tv()

To open the same panels from your own controls:

ui.openPanel(FPlayerPanel.tracks);   // .quality · .speed · .settings
ui.closePanel();
ui.panel;                            // what is open, if anything

What bites

Things that cost an afternoon if nobody tells you first.

downloaded content

A downloaded adaptive stream plays restricted to the qualities you actually fetched. That is already handled inside the package, but if you build the source some other way, with no network the adaptive selector will reach for a quality that is not on disk and the stream will die. Progressive MP4 does not have this problem.

tokens on disk

A download's headers are stored in the index so that, resumed after a reboot, it can authenticate again. That leaves a token in the app's private storage: use short-lived tokens.

odd widths

A video with an odd width — 853×480, for instance — can make MediaCodec fail to configure even though the system reports the format as supported. If one particular clip will not play and the error is "this device can't play this video", check the dimensions before the codec.

offline

When the network drops, playback parks instead of failing, and resumes from the same position once the signal is back. isWaitingForNetwork is what separates "loading" from "waiting for coverage", in case your UI wants to say so.

FSourceType.auto

Leave the type on auto unless your endpoint serves a manifest with no extension and a wrong Content-Type. The engine infers it from the URI and the response better than you can from the path.

Quick check

When integrating into a new app, in this order:

  1. Play a public MP4 with no headers. If this fails, it is Gradle or network configuration, not the player.
  2. Play your real HLS or DASH with the authentication headers in place.
  3. Open the audio and subtitles dialog and confirm your tracks are listed.
  4. Rotate the device, then enter and leave fullscreen: it must not reload.
  5. Cut the wifi mid-playback and turn it back on.
  6. If you use PiP or the media session, test them on a physical device.
emulators

The Android emulator composites the PiP window badly and sometimes leaves it blank even when everything is configured correctly. Do not spend time debugging PiP without having seen it fail on real hardware.
